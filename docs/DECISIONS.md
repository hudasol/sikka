# Decisions

This log records choices made where the build brief was silent or open to more than one reading. Larger architectural choices also have an ADR in `docs/adr/`.

| Id | Decision | Reason |
| --- | --- | --- |
| D01 | The Python environment is a standard `venv` created with `py -3.13 -m venv .venv` on Windows (`python3.13 -m venv .venv` elsewhere). Dependencies are pinned in `requirements.lock`, compiled with `uv pip compile --universal`, and can be installed with either `pip` or `uv`. | Works with plain `pip` on every platform while still giving a reproducible lock file. |
| D02 | The local reporting zone Asia/Dubai is represented as a fixed UTC+04:00 offset. | The zone has no daylight saving, and a fixed offset avoids a dependency on the tz database, which is not bundled with Python on Windows. |
| D03 | `.gitattributes` forces LF line endings. | Generated artefacts are compared byte for byte; per user line ending settings would otherwise change them. |
| D04 | The evaluation harness is its own package, `sikka.evaluation`, placed above the service layer. An extra import contract forbids the product layers (L2 to L7) from importing `sikka.synth`. | The brief requires that the hidden truth file is used only by evaluation. Making it an import rule turns that promise into a checked property. |
| D05 | `sikka check` enforces the 85 percent coverage floor and skips tests marked `slow` or `perf`. Those run in `sikka all` and in CI. | Keeps the fast check fast while the quality gate still holds. |
| D06 | `sikka contract diff` accepts exact versions (`1.0.0`), `v` prefixed versions (`v1.1.0`) and the aliases `v1` (1.0.0), `v1.1` (1.1.0) and `latest`. The brief's example `sikka contract diff v1 v2` is served as `v1 v1.1`, since no 2.0.0 exists. | Only one released and one draft version exist; aliases keep the command short without guessing. |
| D07 | The enumerations the brief leaves open are fixed as follows. Collision type: rear_end, side_impact, head_on, rollover, run_off_road, pedestrian, fixed_object, other. Weather: clear, rain, fog, dust_sand, strong_wind, other. Light: daylight, dark_lit, dark_unlit, dawn_dusk. Surface: dry, wet, sand_covered, damaged, other. Vehicle classes: car, light_goods, heavy_goods, bus, motorcycle. | Small, mutually exclusive sets that cover common coding schemes, including dust and sand conditions. |
| D08 | Range limits used by the models: lanes 1 to 12, speed limit 20 to 160 km/h, mean speed 0 to 250 km/h, contributing factors at most 8 per crash. | Wide enough not to reject plausible values; tighter plausibility checks are conformance rules with their own ids. |
| D09 | Feed files carry the provenance header as the first line of NDJSON (`{"sikka_header": {...}}`), as a `# sikka_header: {...}` comment line in CSV, and as a `sikka_header` member of a GeoJSON FeatureCollection. CSV flattens nested objects with dotted names, writes lists and geometry as JSON text (`[]` for an empty list), and treats an empty cell as an absent field. | One rule for all encodings, readable by standard tools, and still streamable line by line. |
| D10 | Crash feed periods are local calendar years expressed in UTC (2020-12-31T20:00:00Z to 2025-12-31T20:00:00Z). Station counts cover one local week (3 to 10 March 2025) at hourly intervals. True daily traffic is constant across 2021 to 2025. | Keeps the samples small while giving every station a full weekly cycle. Constant traffic is a stated simplification; METHOD and LIMITATIONS repeat it. |
| D11 | A fault's injection rate is the probability that each eligible unit (record, station series or file) receives it, with at least one unit always affected. F20 ground truth includes natural overlaps between producers as well as injected copies, because both are true cross feed duplicates. | Recall is then defined in every evaluation run, and F20 measures what the rule is for. |
| D12 | Committed samples (`data/samples/clean` and `data/samples/broken`, the latter with every fault at 3 percent) contain feeds only. Ground truth is written to `build/` by `sikka generate` and is never committed. | The product must not see the truth; regenerating it is deterministic and cheap. |
| D13 | Producer profiles (detection rate, coordinate noise, time noise, reporting delay, coverage) are invented assumptions listed in `src/sikka/synth/config.py`: A road authority, B police, C emirate level authority, D health sector (fatal and serious crashes only). | The brief asks for different conventions per producer without fixing numbers. |
| D14 | E1 runs each fault in isolation on a clean world, validates only the feeds the fault can touch (plus the registry as context) with only the fault's expected rules, and scores flagged units against the ground truth: rows for record faults, stations for series faults, files for file faults. Seeds are 1001 to 1020. A combined scenario with every fault at once is added to quantify interactions. | Isolation gives a clean per fault precision; the combined run shows what happens when faults overlap. |
| D15 | Conformance scores count a record as failing a family only for error or warning findings at record or series level. Informational findings (possible cross producer duplicates) and file level findings are reported separately. The overall index is the share of records passing every family and is always shown beside the family scores. | Duplicates across producers are expected, not a defect of either producer; file level defects would otherwise wipe out record level information. |
| D16 | `sikka validate` uses the clean sample feeds as reference context by default (`--context samples`), so referential and cross feed rules work for a single uploaded file. | A lone crash feed cannot be checked against a registry or another producer otherwise. |
| D17 | Overview headline "producers conforming" counts producers whose overall index (share of records passing every family) is at least 90 percent, and shows the range implied by the lower and upper Wilson bounds. Rule counts are shown as exact counts without an interval, with a note saying so. | The brief asks for headline figures with intervals; an interval is only shown where it has a statistical meaning. |
| D18 | The demo dataset is the broken sample set (every fault at 3 percent), described on screen as feeds as received. | A clean dataset would show only full scores and would not let a reviewer see defects. |
| D19 | The web app uses hash routing (`/#/validate`). | Static hosts then serve every screen without rewrite rules. |
| D20 | Records with personal data are not dropped: the prohibited fields are removed by the adapter and the rest of the record is kept, with a lineage entry that a field was removed and no trace of its value. | The crash itself is valid evidence; only the personal field is a problem. |
| D21 | Records rejected by harmonisation: duplicates within a feed (`SK-S010`, `SK-X003`), and records with no usable time or location. Crashes more than 250 metres from any segment are kept as canonical crashes but are not counted on a segment. | Counting them would add duplicates or place crashes on the wrong road. |
| D22 | The static snapshot stores lineage in buckets (`v1/lineage-buckets/CC-XY.json` for crashes, one file each for exposure and segments) next to an index (`v1/lineage.json`). | One file per record would mean several thousand files; buckets keep each lookup small. |
| D23 | Daily traffic per segment is the mean flow per minute over the valid intervals of its station, times 1440. Rejected intervals (negative, stuck, unparseable) are excluded and counted in the lineage. | Simple, transparent, and unbiased over a full week; the weekly cycle is fully observed. |
