## Structural (S)

### `SK-S001` Provenance header present and valid

Severity: **error**. Scope: file. Feeds: `road_segments`, `crash_records`, `traffic_counts`.

The file starts with a provenance header that has every required key with a valid value.

Why it matters: Without the header nobody can tell who produced the file, for which period, under which licence, or whether it is synthetic.

How to fix: Add the sikka_header line (NDJSON, CSV) or member (GeoJSON) as described in the contract.

Failing header (differences from a valid header):

```json
{"licence": ""}
```

Passing header: the same header with valid values, for example

```json
{"licence": "Apache-2.0"}
```

### `SK-S002` Declared record count matches

Severity: **error**. Scope: file. Feeds: `road_segments`, `crash_records`, `traffic_counts`.

The header record_count equals the number of records in the file.

Why it matters: A mismatch means the file was truncated, appended to, or the header was copied from another file.

How to fix: Recompute record_count when the file is written, after all filtering.

Failing header (differences from a valid header):

```json
{"record_count": 99}
```

Passing header: the same header with valid values, for example

```json
{"record_count": 1}
```

### `SK-S003` Synthetic flag set in a synthetic repository

Severity: **error**. Scope: file. Feeds: `road_segments`, `crash_records`, `traffic_counts`.

The header synthetic flag is true.

Why it matters: This repository only handles synthetic data. A false flag means real data may have been mixed in, or the flag is wrong; either way the file must not be used here.

How to fix: Set synthetic to true, or remove the file if it holds real records.

Failing header (differences from a valid header):

```json
{"synthetic": false}
```

Passing header: the same header with valid values, for example

```json
{"synthetic": true}
```

### `SK-S010` Identifiers unique within the feed

Severity: **error**. Scope: record. Feeds: `road_segments`, `crash_records`, `traffic_counts`.

Why it matters: Repeated identifiers double count crashes or traffic.

How to fix: Deduplicate on the identifier before export, keeping the latest version.

## Semantic (V)

### `SK-V001` Numeric values inside contract ranges

Severity: **error**. Scope: record. Feeds: `road_segments`, `crash_records`, `traffic_counts`.

Numbers lie inside the range given in the field dictionary, for example counts are not negative and occupancy is at most 100.

Why it matters: Out of range values are impossible by definition and usually come from sign or unit errors.

How to fix: Check the sign convention and the unit of the source system.

Failing record (fields that differ from the passing record):

```json
{"vehicle_count": -40}
```

Passing record:

```json
{"station_id": "STN-DUN-010", "segment_ref": "SEG-DUN-010", "interval_start": "2025-03-03T04:00:00Z", "interval_minutes": 60, "vehicle_count": 3200, "mean_speed_kmh": 92.5, "occupancy_pct": 2.75, "class_counts": {"car": 2400, "light_goods": 320, "heavy_goods": 350, "bus": 110, "motorcycle": 20}, "quality_flag": "ok"}
```

### `SK-V008` Speed unit plausible

Severity: **warning**. Scope: series. Feeds: `traffic_counts`. Needs: registry.

Why it matters: Free flowing traffic near the limit reported at a third of it is the signature of metres per second.

How to fix: Multiply by 3.6 if the source reports m/s, and fix the export unit.

Example: this rule looks at a series or at several feeds together, so a single record cannot show it. Its tests in `tests/conformance` build the failing and passing cases.

### `SK-V009` Occupancy unit plausible

Why it matters: A fraction between 0 and 1 is a valid percent value on its own, so the unit error is only visible against the flow.

How to fix: Multiply by 100 if the source reports a fraction.

Example: this rule looks at a series or at several feeds together, so a single record cannot show it. Its tests in `tests/conformance` build the failing and passing cases.

### `SK-V013` Daily profile aligned with the network

Severity: **warning**. Scope: series. Feeds: `traffic_counts`.

How to fix: Convert station timestamps from Asia/Dubai to UTC before export.

Example: this rule looks at a series or at several feeds together, so a single record cannot show it. Its tests in `tests/conformance` build the failing and passing cases.

## Cross feed (X)

### `SK-X001` Possible duplicate across producers

Severity: **info**. Scope: record. Feeds: `crash_records`. Needs: other crash feeds.

A crash has a record in another producer's feed within 20 minutes and 200 metres.

Why it matters: The same crash is often reported by several entities. Counting each report would inflate crash counts; the harmonisation layer resolves these pairs.

How to fix: No action is needed from the producer; shared identifiers would make matching exact.

Example: this rule looks at a series or at several feeds together, so a single record cannot show it. Its tests in `tests/conformance` build the failing and passing cases.

### `SK-X002` No systematic time offset between producers

Severity: **warning**. Scope: record. Feeds: `crash_records`. Needs: other crash feeds.
